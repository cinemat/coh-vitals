# Задача 01 — кеш сторінки для рекламного трафіку (fbclid / gclid / utm)

**Сторінка:** https://childrenheroes.org/en/support-ukrainian-children-who-lost-parents-2/ (`donate-en`)
**Пов'язано з аудитом:** 2.4 «Edge-кеш анонімного HTML» + 2.3 (WCML) — `childrenheroes-performance-audit-plan-2026-07-31.pdf`
**Створено:** 2026-09-29
**Статус:** [ ] не почато

## Проблема (заміряно 2026-09-29)

| Запит | TTFB | Заголовки |
|---|---|---|
| `…/lost-parents-2/` | **0.30–0.39 s** | WP Super Cache HIT, `cf-cache-status: DYNAMIC` |
| `…/lost-parents-2/?fbclid=…` | **2.46 s** | `no-cache, no-store`, PHP-рендер |
| `…/lost-parents-2/?gclid=…&utm_source=google` | **1.46 s** | `no-cache, no-store`, PHP-рендер |

- Кожен унікальний `fbclid`/`gclid` — промах кешу → повний рендер WordPress (43 плагіни).
- Некешована відповідь ставить 3 кукі WooCommerce Multilingual: `wcml_client_currency`, `wcml_client_currency_language`, `wcml_client_country` → через `Set-Cookie` її не кешує й Cloudflare.
- Наслідок у CrUX (реальні користувачі, 28.09): TTFB **2.9 s mobile / 2.1 s desktop**, FCP 4.4 s, LCP 5.9 s mobile — усе SLOW. У лабораторії TTFB 0.3 s, тому PSI-бал цю проблему не показує.

**Мета:** будь-який URL з рекламними параметрами віддається з кешу (TTFB ≤ 0.4 s), атрибуція (gclid/fbclid/UTM у браузері) не ламається.

## Крок 1 — WP Super Cache: ігнорувати трекінг-параметри (головне)

- [ ] 1.1 Зробити бекап `wp-content/wp-cache-config.php`
- [ ] 1.2 Перевірити версію WP Super Cache ≥ 1.11 (Плагіни). Якщо нижче — оновити
- [ ] 1.3 **Settings → WP Super Cache → Advanced** → увімкнути опцію ігнорування tracking parameters (у конфігу це `$wpsc_ignore_tracking_parameters = 1;`)
- [ ] 1.4 У списку параметрів (`$wpsc_tracking_parameters`) мають бути:
  ```
  fbclid
  gclid
  gbraid
  wbraid
  gad_source
  msclkid
  ttclid
  twclid
  li_fat_id
  yclid
  mc_cid
  mc_eid
  _ga
  _gl
  utm_source
  utm_medium
  utm_campaign
  utm_term
  utm_content
  utm_id
  ```
- [ ] 1.5 Зберегти → **Delete Cache** (очистити весь кеш)
- [ ] 1.6 Якщо опції в UI немає — прописати вручну у `wp-cache-config.php`:
  ```php
  $wpsc_ignore_tracking_parameters = 1;
  $wpsc_tracking_parameters = array( 'fbclid', 'gclid', 'gbraid', 'wbraid', 'gad_source', 'msclkid', 'ttclid', 'twclid', 'li_fat_id', 'yclid', 'mc_cid', 'mc_eid', '_ga', '_gl', 'utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content', 'utm_id' );
  ```

**Перевірка кроку 1** (з терміналу; кожен запуск — новий унікальний параметр):
```bash
U="https://childrenheroes.org/en/support-ukrainian-children-who-lost-parents-2/"
for q in "" "?fbclid=t$RANDOM" "?gclid=t$RANDOM&utm_source=google&utm_campaign=x"; do
  curl -s -o /dev/null -D /tmp/h -w "ttfb=%{time_starttransfer}s  $q\n" -A "Mozilla/5.0 (Linux; Android 10) Mobile" "$U$q"
  grep -iE "cache-control|set-cookie" /tmp/h
done
curl -s "$U?fbclid=t$RANDOM" | tail -c 300   # має бути коментар "Cached page generated by WP-Super-Cache"
```
- [ ] 1.7 Усі три запити: TTFB ≤ 0.4 s, немає `no-store`, немає `Set-Cookie: wcml_*`
- [ ] 1.8 В кінці HTML є `Cached page generated by WP-Super-Cache`

## Крок 3 — Cloudflare: кеш анонімного HTML на edge (після кроків 1–2)

Робити лише коли крок 1 підтверджено, бо з `Set-Cookie` Cloudflare все одно не кешуватиме.

- [ ] 3.1 Cloudflare → Caching → **Cache Rules** → Create rule «HTML anonymous»
  - **When** (Custom filter expression):
    ```
    (http.host eq "childrenheroes.org"
     and not starts_with(http.request.uri.path, "/wp-admin")
     and not starts_with(http.request.uri.path, "/wp-login")
     and not starts_with(http.request.uri.path, "/wp-json")
     and not http.request.uri.path contains "/cart"
     and not http.request.uri.path contains "/checkout"
     and not http.request.uri.path contains "/my-account"
     and not http.request.uri.path contains "admin-ajax.php"
     and not http.cookie contains "wordpress_logged_in"
     and not http.cookie contains "wp-postpass"
     and not http.cookie contains "woocommerce_items_in_cart"
     and not http.cookie contains "comment_author"
     and http.request.method in {"GET" "HEAD"})
    ```
  - **Then:** Eligible for cache
  - **Edge TTL:** Ignore cache-control header → **120 s** (коротко, щоб не потрібен був purge при редагуванні)
  - **Browser TTL:** Respect origin
  - **Cache key → Query string:** якщо на тарифі доступно «Exclude» — виключити той самий список параметрів з кроку 1.4; якщо ні — залишити за замовчуванням (тоді edge-кеш працює для URL без параметрів, а URL з параметрами закриває крок 1)
- [ ] 3.2 Перевірка: `curl -sI "$U" | grep cf-cache-status` → після 2-го запиту `HIT`
- [ ] 3.3 Залогінитись в адмінку → сторінки не з кешу (адмін-бар видно, `cf-cache-status` ≠ HIT)
- [ ] 3.4 Відредагувати сторінку → зміни видно максимум через 2 хв

## Відкат

- WP Super Cache: повернути `wp-cache-config.php` з бекапу (1.1) → Delete Cache
- Cloudflare: вимкнути правило «HTML anonymous»
